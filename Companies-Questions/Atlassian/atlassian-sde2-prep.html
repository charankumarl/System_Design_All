Recurring theme across every write-up: interviewers push for clean, extensible, working code with tests — not whiteboard pseudocode — and in system design they explicitly penalize candidates who don't ask clarifying questions before diving in, even on "obvious" requirements.

Top Focus — prepare these first

P0Tag Management System (HLD)

The single most-repeated Atlassian system design question, across 2022–2026 reports, in almost every variant (tag design, tag management for Jira/Confluence, tag popularity tracking, top-K popular tags). If you prepare one HLD deeply, make it this one.

P0Snake Game (LLD / Code Design)

Most-repeated code-design prompt. Always comes with live-changing requirements (wrap-around vs. game-over) and concurrency follow-ups (simultaneous key presses). Practice writing it with unit tests, not just logic.

P0API Rate Limiter (LLD)

Second most-repeated LLD/code-design prompt. Token bucket + sliding window + per-user/per-API limiting + thread safety. One report had the interviewer push toward a Trie-based "Middleware Router" variant — know how routing/rate-limiting can combine.

P1Web Crawler / URL Scraper (HLD)

Third most-repeated HLD prompt. Queue + worker + dedup + retries. One candidate was downleveled here specifically for skipping clarifying questions — ask about scale, politeness/rate limits, and freshness before architecture.

P1Intervals / Scheduling DSA

Merge Intervals, Tennis Court Booking (scheduling + conflict detection), and "mostly interval" problems show up repeatedly in the DSA rounds. This topic has outsized weight relative to how little most people revise it.

P1Top-K / Frequency DSA

Top-K Frequent Elements/Words, Stock Price Fluctuation (LC 2034), tag-popularity tracking (incr/decr/most-popular) — all heap + hashmap pattern. Shows up in both DSA rounds and as the backbone of the Tag Management HLD.

2. LLD / Code Design

Atlassian's official guide calls this round "Code Design", not classic LLD — you're expected to produce real, running, testable code (Java), not just a class diagram. Favor SOLID, clear interfaces, and at least a couple of unit tests for every design.

3. HLD / System Design

60-minute practical discussion. For every question below: state FR/NFR out loud, ask 3–5 clarifying questions before architecture (candidates get downleveled for skipping this), then cover API → data model → high-level architecture → scaling/bottlenecks → failure modes.
